# 0.4.0 界面、预设条目开关与 401 处理

## 1. 日夜主题

标题栏新增 ☀/☾ 按钮，一键切换日间/夜间配色，选择写入酒馆扩展设置。启动时默认跟随系统 `prefers-color-scheme`；用户手动切换后固定为所选主题。

界面调整为卡片式连接设置、圆角字段、44px 触控按钮、可滚动条目列表和更清晰的连接状态。未在安卓 APK 真机检查实际字体、主题变量和软键盘遮挡。

## 2. 401 报错

本次做了三件事：

1. 发送前清理口令的首尾空白、`Bearer ` 前缀、包裹引号和内部空白。
2. 在请求前识别明显的错误类型：GitHub token、Google JSON、少于 16 字符的口令，直接给出提示，不发送请求。
3. 401 时显示 requestId，并提示核对 Secret Manager 与 Cloud Run revision。

**仍有一个环境因素不能由前端消除：** 如果 Secret Manager 更新过而 Cloud Run 仍使用旧 revision，旧口令会继续被接受、新口令会 401。可用下面的命令让服务加载最新 secret：

```bash
gcloud run services update st-vertex-polish \
  --region us-central1 \
  --update-secrets POLISH_ACCESS_TOKEN=polish-access-token:latest
```

不要重新生成口令，除非确认 Secret 中的值已经丢失。重新生成后需同步更新 Secret 并重新部署。

## 3. 预设条目开关

选择酒馆预设并刷新后，窗口出现“预设条目开关”。它是只读预览加请求级覆盖：

- 每条显示名称、角色、是否占位/空。
- 文本条目可勾选/取消，仅影响本扩展下一次润色请求的 system instruction。
- marker 和空条目显示为“占位·跳过/空·跳过”，不可启用。
- “恢复预设默认”清除当前预设的本地覆盖记录。
- 不调用 `selectPreset`，不写回 `/api/presets`，不改变酒馆主聊天设置。
- 覆盖记录按预设名称保存在扩展设置中；预设改名后旧记录不会自动迁移。

读取仍使用 SillyTavern 1.19.0 的 `getPresetManager('openai').getPresetList()`；参考实现与许可证说明见 `FIX-0.3.2.md`。参考插件没有可用许可证，未复制其代码。

## 4. 验证

执行 `node tests/run-all.js`：48 项通过。新增条目列表/覆盖、主题切换、显式口令保存、401 后恢复。未在真实的 Android APK、酒馆浏览器、真实 Vertex 凭据下执行，不能标记实机通过。

建议更新后按顺序检查：

1. 扩展版本为 0.4.0，窗口能打开。
2. 点“刷新”能列出酒馆预设。
3. “预设条目开关”能展开，文本条目可勾选。
4. 取消一个条目后开始润色，发送内容中的该条规则消失（可用“查看发送内容”或日志确认；当前版本没有完整发送内容面板，这是后续可补项）。
5. 日夜按钮切换后窗口配色变化，刷新后保持。
6. 口令框输入后点击“保存连接配置”不会清空；验证失败时显示可理解原因。
